# 多聊天绑定与身份路由 — 规范

> 让多个智能体会话分别连接不同飞书聊天，并根据群聊、本人私聊和同事私聊选择合适身份。
> 状态：已确认；确认来源：用户于 2026-09-23 提出的四项行为要求及随后确认“不同聊天标识应支持多个 Codex 会话”。

## 1. 产品总览

### 1.1 为什么做

- **问题与用户**：当前插件把本机所有聊天限制为一个活动绑定。用户同时让不同 Codex 任务服务不同聊天时会互相阻塞，并且每次连接都需要临时判断机器人或用户身份。
- **事实依据**：`session.mjs` 只保存一个 `connection`；本次实际连接中，验收群绑定阻止了另一个任务连接机器人私聊。官方 `lark-cli` 支持用户与机器人身份读取聊天，也支持用户身份将应用机器人加入群聊。
- **价值与时机**：允许不同聊天独立工作，才能覆盖一个智能体帮助同事、另一个智能体接受用户控制等并行情景；固定身份选择规则可以减少误用身份和重复确认。
- **替代方案**：人工停止再切换聊天仍会中断另一项任务，不满足并行使用目标。

### 1.2 来源结构对齐

| 来源 | 原始章节或需求 | 规格落点 | 对齐说明 |
|---|---|---|---|
| 用户需求描述 | 不同聊天标识支持多个 Codex 会话 | `2.1 多聊天并行连接` | 直接对应 |
| 用户需求描述 | 群聊默认机器人；不在群时用户拉机器人入群 | `2.2 群聊连接` | 直接对应 |

| 用户需求描述 | 与同事私聊时使用用户身份，帮助同事解决问题 | `2.4 同事私聊连接` | 直接对应 |
| 用户需求描述 | 多个机器人配置档案时先询问 | `2.5 配置档案选择` | 直接对应 |

### 1.3 整体产品体验

- **目标用户与场景**：用户从多个 Codex 或 Claude Code 会话分别连接多个飞书聊天。
- **端到端结果**：不同聊天可以同时保持独立绑定、唤醒和扫描位置；连接时自动选择符合聊天用途的身份，并明确告知所选配置档案和身份。
- **共享产品规则**：同一聊天同时最多由一个智能体会话处理；每个智能体会话仍只绑定一个聊天。所有飞书命令显式指定配置档案和身份，失败时不静默切换。
- **总体范围**：本规格覆盖多聊天绑定、默认身份选择、机器人入群恢复和多机器人选择。

### 1.4 调研发现

- `plugins/lark-connect/skills/lark-chat-session/scripts/session.mjs`：当前 `connection.json` 只有一个活动连接，`start` 遇到任何已有连接都会返回 `ALREADY_BOUND`。
- `lark-cli im chat.members create --help`：用户身份可以把 `app_id` 类型的机器人加入自己已在的群；调用者仍受群权限、租户边界和应用权限约束。
- `lark-cli profile list`、`whoami --as bot` 与 `/open-apis/bot/v3/info`：可以枚举配置档案，并核实每个可用机器人的名称、应用标识和机器人标识。
- 当前仓库没有 `docs/rules/spec/`，本规格没有额外项目级需求规则。

## 2. 产品需求分项

### 2.1 多聊天并行连接

#### 2.1.1 原始产品需求

- **来源**：用户需求描述#多聊天连接。
- **原始需求**：只要飞书聊天标识不同，就允许多个 Codex 会话分别连接。

#### 2.1.2 用户可感知行为

- **目标用户与场景**：用户同时让多个智能体会话服务不同聊天。
- **触发与前置条件**：每个会话选择的聊天标识不同，且所需身份能读取对应聊天。
- **主要行为**：每个绑定独立保存聊天、会话、连接代次和扫描位置；检查、推进位置或停止一个绑定不影响其他绑定。
- **成功结果**：不同聊天可以同时保持活动状态并分别持续响应。
- **失败与边界行为**：第二个会话尝试连接已绑定聊天时被拒绝，并指出现有占用；同一会话尝试直接连接第二个聊天时要求先停止或明确切换。
- **兼容要求**：仍不保存凭据、消息正文或逐消息账本；新版接管旧版已占用的聊天前，先停止旧绑定和唤醒；本次不提供旧状态自动迁移。

#### 2.1.3 交互设计

- 查看状态时，当前会话只看到自己的绑定；管理场景可列出全部活动绑定。
- 同一聊天冲突时应说明占用它的运行时和会话，而不是笼统报告“已有连接”。

#### 2.1.4 分项范围边界

- **本项包含**：不同聊天并行、同聊天互斥、绑定级检查点与停止。
- **本项不包含**：一个智能体会话同时处理多个聊天；集中式守护进程或消息数据库。
- **引用共享规则**：适用 `1.3` 的单聊天单处理者及显式身份规则。

#### 2.1.5 验收映射

- `VAL-MULTI-CHAT-001`：不同聊天可并行绑定。
- `VAL-MULTI-CHAT-002`：同一聊天不能由两个会话同时绑定。
- `VAL-MULTI-CHAT-003`：检查点和停止只影响目标绑定。

### 2.2 群聊连接

#### 2.2.1 原始产品需求

- **来源**：用户需求描述#群聊身份。
- **原始需求**：连接群聊默认使用机器人身份；机器人不在群时，先尝试用用户身份把同一配置档案的机器人拉入群。

#### 2.2.2 用户可感知行为

- **触发与前置条件**：用户指定群聊，所选配置档案至少有可用机器人身份。
- **主要行为**：先以机器人身份查找并核实群成员和历史；机器人不在群时，以同一配置档案的用户身份定位群聊并尝试邀请该机器人，随后重新用机器人身份核实。
- **成功结果**：绑定最终以机器人身份建立，并明确告知配置档案、机器人及必要的入群动作。
- **失败与边界行为**：用户身份缺失、用户不在群、没有邀请权限、机器人不可用或邀请后仍不可读时，报告实际失败并停止连接；不得改为用户身份继续绑定群聊。

#### 2.2.3 交互设计

- 执行邀请前明确说明将用哪个配置档案的用户身份邀请哪个机器人。
- 邀请失败时保留上游错误和可采取的下一步，不声称已连接。

#### 2.2.4 分项范围边界

- **本项包含**：普通群与话题群的机器人优先连接、一次用户身份入群恢复。
- **本项不包含**：自动调整群权限、群管理员、应用可用范围或审批入群请求。

#### 2.2.5 验收映射

- `VAL-GROUP-IDENTITY-001`：机器人已在群时直接以机器人连接。
- `VAL-GROUP-IDENTITY-002`：机器人不在群时由用户身份邀请并重新核实。
- `VAL-GROUP-IDENTITY-003`：邀请失败不降级为用户身份连接。

### 2.3 本人私聊连接

#### 2.3.1 原始产品需求

- **来源**：用户需求描述#本人私聊。
- **原始需求**：连接用户与智能体机器人的私聊时使用机器人身份，让用户通过飞书控制对应智能体会话。

#### 2.3.2 用户可感知行为

- **触发与前置条件**：用户表达“跟我的私聊”等本人控制意图，并已选择可用机器人。
- **主要行为**：用所选配置档案的机器人身份定位该机器人与当前登录用户的单聊并连接；不能可靠定位时使用唯一挑战消息确认聊天。
- **成功结果**：飞书中发给机器人的新消息由当前智能体会话按机器人身份处理和回复。
- **失败与边界行为**：不能唯一定位或机器人不能读取历史时停止，不改用用户自己的收藏式私聊或用户身份。

#### 2.3.3 分项范围边界

- **本项包含**：当前登录用户与所选机器人的单聊。
- **本项不包含**：用户与自己的“发给自己”会话、用户与其他机器人的会话。

#### 2.3.4 验收映射

- `VAL-PRIVATE-OWNER-001`：本人控制私聊始终使用所选机器人身份。
- `VAL-PRIVATE-OWNER-002`：单聊不能唯一确认时不建立绑定。

### 2.4 同事私聊连接

#### 2.4.1 原始产品需求

- **来源**：用户需求描述#同事私聊。
- **原始需求**：连接用户与同事的私聊时使用用户身份，由智能体会话帮助同事解决问题。

#### 2.4.2 用户可感知行为

- **触发与前置条件**：用户指定一名同事，所选配置档案的用户身份已授权且能访问该单聊。
- **主要行为**：以用户身份搜索并确认目标同事的单聊，检查该聊天全部新消息并按需回复。
- **成功结果**：回复以用户本人身份发出并关联同事原消息。
- **失败与边界行为**：同名候选不唯一时先让用户选择；用户身份不可用或聊天不可读时报告实际错误，不改用机器人身份。

#### 2.4.3 分项范围边界

- **本项包含**：用户与一名真人同事的已有单聊。
- **本项不包含**：代表用户新建外部联系关系、批量联系多人或自动处理所有私聊。

#### 2.4.4 验收映射

- `VAL-PRIVATE-COLLEAGUE-001`：同事私聊使用用户身份。
- `VAL-PRIVATE-COLLEAGUE-002`：候选或身份不明确时不建立绑定。

### 2.5 配置档案选择

#### 2.5.1 原始产品需求

- **来源**：用户需求描述#多机器人配置档案。
- **原始需求**：本机绑定多个机器人配置档案时，连接前先询问使用哪个机器人。

#### 2.5.2 用户可感知行为

- **触发与前置条件**：本机存在两个或以上通过身份检查的机器人配置档案。
- **主要行为**：展示机器人名称及配置档案名，让用户选择；选择结果同时确定后续使用的机器人身份及同档案用户身份。
- **成功结果**：所有查找、邀请、读取和回复都显式使用已选择配置档案。
- **失败与边界行为**：没有选择前不查找目标聊天、不执行邀请、不建立绑定；身份失败时不静默换到其他配置档案。

#### 2.5.3 分项范围边界

- **本项包含**：可用机器人配置档案的发现与选择。
- **本项不包含**：修改默认配置档案、合并不同配置档案的用户与机器人身份。

#### 2.5.4 验收映射

- `VAL-PROFILE-SELECTION-001`：多个可用机器人时必须先选择。
- `VAL-PROFILE-SELECTION-002`：单个可用机器人时直接选用并明确告知。

## 3. 整体不做

- 不增加本仓库守护进程、模型上下文协议服务或飞书接口包装层。
- 不让一个会话同时绑定多个聊天。
- 不自动更改群权限、应用权限或联系人关系。
