# 飞书协作插件轻量化迁移 — 规范

> 让 Codex 和 Claude Code 智能体通过已配置的飞书身份持续参与团队聊天，同时减少安装、维护和使用本仓库专用工具的负担。
> 状态：产品方向已确认；架构与实施方案另行设计。

## 1. 产品总览

### 1.1 为什么做

- **问题与用户**：团队成员希望在飞书群聊或机器人单聊中交给本地智能体任务，并在原聊天收到结果。现有插件为此提供自有命令行工具、守护进程和模型上下文协议工具，用户需要配置、启动和排查多层本地组件。
- **事实依据**：[README](../../../README.md) 描述了插件安装、守护进程、会话绑定、等待、回复和确认流程；当前[运行状态](../../../src/daemon/runtime.js)保存在内存中，进程重启后绑定和队列会丢失。用户指出现有 `lark-cli` 已支持配置档案、用户与机器人身份、消息事件及更广的飞书操作；2026 年 9 月 22 日本机 1.0.92 版本的命令帮助和消息事件定义已核实这些基础能力。
- **价值与时机**：用户已经明确提出以飞书命令行工具和插件技能承接常用能力，并要求开始规格设计。迁移若成功，使用者仍能完成现有协作任务，维护者则可以减少重复建设和故障面。本需求的价值出口为“值得做”。
- **更小的替代**：保持现状并仅在技能中增加 `lark-cli` 指南，能扩展飞书操作，却不能消除双套配置、监听和消息处理入口。直接让智能体每次临时查命令可减少插件代码，但常用多步操作容易遗漏身份、过滤、回复关系或确认步骤。

### 1.3 整体产品体验

- **目标用户与场景**：团队成员在飞书聊天中向机器人提出需求；本地 Codex 或 Claude Code 会话代表已选择的身份参与聊天。会话主人也可以要求智能体执行其已获授权的其他飞书操作。
- **端到端结果**：用户选择飞书身份和目标聊天后，智能体理解近期上下文、发现符合条件的新消息、处理任务、以所选身份在原消息下回复并标记完成。机器人和用户身份都能在会话暂时无人值守时继续发现待处理消息；恢复后不因重复检查而重复回复。
- **共享产品规则**：每次飞书操作必须清楚使用哪个配置档案、机器人或用户身份；不得暗中切换默认配置档案。机器人身份下，群聊只有明确提及目标机器人的新消息才触发任务，已连接的机器人单聊无需提及。用户身份下，明确连接的聊天中的全部新消息都交给智能体判断，只有需要回应时才回复；不得把其他聊天的消息交给当前会话。重复接收同一飞书消息不得产生重复回复。涉及外部写入时遵循当前会话的用户授权边界。
- **总体范围**：以聊天协作为核心，覆盖配置与身份选择、发现并连接目标聊天、上下文和消息处理、持续响应与恢复，以及 Codex 与 Claude Code 的插件使用体验。其他飞书操作由智能体按用户要求调用已获授权的上游能力；插件不承诺逐项封装飞书全部功能。

### 1.4 调研发现

- 现有插件通过[守护进程](../../../src/daemon/runner.js)与[模型上下文协议工具](../../../src/mcp/server.js)提供飞书收发、会话绑定和排队；[README](../../../README.md)承诺同一时间只连接一个聊天与智能体会话。
- 当前群消息过滤依赖飞书结构化提及信息，单聊不要求提及；现有[运行状态](../../../src/daemon/runtime.js)还承担去重、等待、领取和确认状态。
- 本机 `lark-cli event schema im.message.receive_v1 --json` 显示该事件仅支持机器人身份，提供消息、聊天、发送者和提及标识；`lark-cli` 同时提供聊天查询、历史消息、回复、附件与反应命令。用户身份可按目标聊天和时间范围读取历史并以本人身份回复；事件输出不等同于会话唤醒或完成状态。
- Codex 当前会话的计划任务可按分钟间隔返回同一会话；Claude Code `/loop` 可在会话保持打开期间定期运行。它们为用户身份的无人值守检查提供运行时入口，但实际响应依赖本地机器、运行时和飞书授权可用。
- 飞书命令行工具已有问题报告指出：在话题群使用带时间范围的聊天历史查询时，旧话题中的新回复可能被漏掉；部分跨组织群不允许使用用户身份读取消息历史。前者需在真实验收中覆盖，后者必须作为不可用状态告知用户，不能把空结果当作没有新消息。
- 当前[项目规则](../../../AGENTS.md)禁止正式路径依赖 `lark-cli`。实施本规格前，架构设计必须明确修改这一仓库约束及现有用户的切换方式。仓库没有 `docs/rules/spec/`，无项目专属规格规则。

## 2. 产品需求分项

### 2.1 选择飞书身份

#### 2.1.1 原始产品需求

- **来源**：本轮用户描述“`lark-cli` 支持 profile，可以分不同机器人或者用用户身份进入飞书聊天工作”。
- **原始需求**：同一位使用者可以明确选择要使用的飞书应用及操作身份；机器人和用户身份都能在已连接聊天中持续响应，不再受本仓库单份应用配置限制。

#### 2.1.2 用户可感知行为

- **触发与前置条件**：用户首次连接聊天，或要求切换机器人、改用本人身份执行飞书操作。
- **主要行为**：智能体展示将使用的配置档案和身份；连接聊天及后续操作沿用本次选择。更换配置档案或身份需根据用户当次指令重新确认操作目标。
- **成功结果**：机器人或用户身份收到符合各自触发规则的消息后，都可在所选聊天中以相应身份回复；智能体可以说明当前有效身份。
- **失败与边界行为**：配置档案不存在、凭据无效或权限不足时，明确指出受影响的身份及恢复办法；不得自动退回另一身份执行。

#### 2.1.3 交互设计

- 选择目标身份时，智能体以可读名称说明“将使用飞书配置「{配置档案}」的{机器人／用户}身份”；身份不明确时先询问，不根据当前机器的全局默认值猜测。
- 配置档案缺失时说明“未找到飞书配置「{配置档案}」，请先完成该身份的配置”。权限不足时说明“当前飞书身份无权完成这项操作，请检查对应应用权限或用户授权”。

#### 2.1.4 分项范围边界

- **本项包含**：多配置档案选择、机器人与用户身份区分、缺失凭据和授权的可恢复反馈。
- **本项不包含**：在本仓库保存、展示或迁移明文应用密钥；允许机器人身份代替用户访问其私人资源。

#### 2.1.5 验收映射

- `VAL-IDENTITY-001`：指定身份贯穿一次协作流程。
- `VAL-IDENTITY-002`：身份不可用时不自动改用其他身份。
- `VAL-IDENTITY-003`：用户身份可代表本人参与已连接聊天。

### 2.2 进入目标聊天

#### 2.2.1 原始产品需求

- **来源**：[README](../../../README.md)“搜索和绑定聊天”；本轮用户描述“用技能和简单脚本组合常用操作”。
- **原始需求**：用户能够用群名或机器人单聊进入目标聊天，无需自行查找聊天标识；进入后智能体了解近期协作背景。

#### 2.2.2 用户可感知行为

- **触发与前置条件**：用户指定聊天及飞书身份，目标机器人已加入群聊，或用户能访问目标单聊。
- **主要行为**：智能体按所选身份找到目标聊天；候选不唯一时请用户选择。用户身份可选择本人有权访问的群聊或单聊；机器人身份可选择机器人可见群聊或单聊。进入聊天后可读取近期消息、参与者及其他机器人，供后续回复或提及使用。
- **成功结果**：当前智能体会话只处理已选择聊天的后续消息；用户可以知道正在响应哪个聊天、使用哪个身份。
- **失败与边界行为**：找不到群聊时提示确认名称或将机器人加入群；无法直接发现单聊时提供可由用户完成的安全发现方式。用户虽是群成员但开放接口禁止读取该群历史时，不得声称连接后能持续响应，应说明该聊天不可用及权限或平台限制。目标聊天已由其他会话响应时，不得静默接管；用户明确要求接管后，旧会话停止响应。
- **兼容要求**：保留群聊与机器人单聊两种协作入口，并增加用户身份下的群聊与单聊入口；默认保持同一时间只连接一个聊天与一个智能体会话的现有约束。

#### 2.2.3 交互设计

- 候选聊天不唯一时说明“找到多个匹配聊天，请选择要连接的聊天”；找不到群聊时说明“未找到目标群聊，请确认名称及所选机器人是否已加入该群”。
- 进入成功时说明“已连接「{聊天名称}」，使用「{配置档案}」的{机器人／用户}身份”；用户可随时要求停止或更换目标聊天。
- 单聊需要用户发送验证文本时，智能体给出本次专用文本、目标机器人及等待结果；超时说明“未收到匹配的单聊验证消息，请确认发送给了当前机器人后重试”。

#### 2.2.4 分项范围边界

- **本项包含**：群聊候选查找、单聊发现、目标确认、近期上下文及参与者查询、显式接管和停止。
- **本项不包含**：自动连接搜索结果中的多个聊天、按话题同时连接不同会话。
- **引用共享规则**：`1.3` 的身份选择、聊天隔离与单连接约束。

#### 2.2.5 验收映射

- `VAL-CHAT-001`：能定位并连接唯一目标聊天。
- `VAL-CHAT-002`：歧义、找不到及单聊发现失败时有明确恢复路径。
- `VAL-CHAT-003`：不会静默接管或跨聊天投递。
- `VAL-CHAT-004`：连接后可读取协作背景和参与者。
- `VAL-CHAT-005`：用户身份可进入本人有权访问的群聊或单聊。

### 2.3 处理聊天消息

#### 2.3.1 原始产品需求

- **来源**：[README](../../../README.md)“发送回复和 @”；本轮用户描述“接收事件，并通过技能与脚本完成原工具相关功能”。
- **原始需求**：智能体接收应处理的消息，利用必要上下文和附件完成任务，再在原聊天给出可追踪的结果。

#### 2.3.2 用户可感知行为

- **触发与前置条件**：目标聊天已连接；机器人身份按提及或单聊规则处理，用户身份检查所选聊天的全部新消息。
- **主要行为**：智能体识别发送者、消息内容、提及对象、回复关系和资源；需要时读取聊天背景、下载附件或查询参与者。处理后在原消息下回复文本、图片、视频或文件，按需提及人类成员或其他机器人；完成后给原消息添加确认反应。
- **成功结果**：发起人能从原消息看到回复关系和处理完成标记；同一消息即使重复投递也不会收到重复回复。
- **失败与边界行为**：机器人身份下没有明确提及的普通群消息不触发任务；用户身份下的普通消息也要进入判断，但不要求逐条回复。资源读取失败或无权限时，智能体说明受阻原因。回复失败时不标记完成；回复成功而确认标记失败时明确显示部分完成状态，恢复后补确认，不重复回复。超时但没有新消息不视为处理失败。
- **兼容要求**：允许人类与其他机器人参与同一群的协作，但不得因自身发出的消息形成自动回复循环。用户身份下，智能体的回复与用户本人发送的合格指令可能显示为同一发送者；后者仍应被处理。

#### 2.3.3 交互设计

- 完成时优先在原消息下回复，并用现有 `OK` 反应表示已处理；处理失败或尚未完成时不显示该完成标记。
- 回复已发送但完成标记失败时，在智能体会话中说明“回复已发送，但确认标记失败；将补做确认，不会重复回复”。无法获取附件时说明“无法读取这条消息的附件，请检查权限或重新发送”。

#### 2.3.4 分项范围边界

- **本项包含**：消息过滤、上下文和附件读取、原消息回复、媒体与文件、提及参与者、确认及部分失败反馈。
- **本项不包含**：把飞书任意消息自动解释为有权执行本地高风险操作的命令。
- **引用共享规则**：`1.3` 的身份、聊天隔离、明确提及和重复消息规则。

#### 2.3.5 验收映射

- `VAL-MESSAGE-001`：仅符合条件的新消息触发当前会话。
- `VAL-MESSAGE-002`：消息的协作信息与附件可用于任务处理。
- `VAL-MESSAGE-003`：回复关联原消息，支持现有产物和提及场景。
- `VAL-MESSAGE-004`：完成标记与实际回复结果一致。
- `VAL-MESSAGE-005`：重复事件和自身消息不会造成重复回复循环。
- `VAL-MESSAGE-006`：用户身份检查所选聊天的全部新消息并按需回复。

### 2.4 持续响应与恢复

#### 2.4.1 原始产品需求

- **来源**：本轮用户确认“保留持续响应”；[README](../../../README.md)“长时间等待聊天消息”。
- **原始需求**：会话不需要始终有人盯着，也能继续处理目标聊天的后续消息；临时监听结束或中断后，用户消息不应被静默遗漏。

#### 2.4.2 用户可感知行为

- **触发与前置条件**：用户已要求当前会话持续响应，且未要求停止。
- **主要行为**：机器人身份的会话活跃时等待新消息；用户身份和无人值守状态按运行时允许的方式检查目标聊天。重新开始监听或检查时，先识别上次检查以来可能未处理的消息，再继续接收新消息。
- **成功结果**：机器人和用户身份在会话暂时无人值守期间收到的合格消息，都在下一次成功检查后被处理；临时等待超时不会自动解除连接。若目标为话题群，旧话题中的新回复也在应检查的范围内。重复检查和重新连接不会重复回复已处理消息。
- **失败与边界行为**：飞书不可达、授权过期、智能体运行时无法唤醒、历史消息无法读取或检查范围不完整时，向会话主人明确报告持续响应受阻与可能的空窗，不得将不完整的结果报告为“没有新消息”；恢复后重查可访问的历史。用户明确停止、切换目标或撤销身份后，旧聊天不再触发该会话。
- **兼容要求**：Codex 和 Claude Code 均支持持续响应；响应速度受各自运行时的唤醒能力约束，不能把“实时”解释为无人值守时零延迟。

#### 2.4.3 交互设计

- 开始时说明“已开始响应「{聊天名称}」；会话无人值守时将在后续检查中继续处理新消息”。停止时说明“已停止响应「{聊天名称}」”。
- 持续响应不可用时说明“飞书消息检查已中断；期间可能有未处理消息。恢复连接后会重查可访问的聊天历史”，并给出实际失败原因。

#### 2.4.4 分项范围边界

- **本项包含**：活跃等待、无人值守检查、监听空窗补查、重复处理防护、停止与恢复状态反馈。
- **本项不包含**：承诺飞书或智能体运行时故障期间的固定响应时限；恢复飞书已经无法提供的历史消息。
- **引用共享规则**：`1.3` 的聊天隔离与重复消息规则。

#### 2.4.5 验收映射

- `VAL-CONTINUITY-001`：活跃和无人值守状态都可继续发现消息。
- `VAL-CONTINUITY-002`：监听空窗中的可访问消息可补查且不重复处理。
- `VAL-CONTINUITY-003`：失败、恢复和停止状态对会话主人可见。
- `VAL-CONTINUITY-004`：用户身份在无人值守期间可检查并处理目标聊天的合格消息。

### 2.5 使用其他飞书能力

#### 2.5.1 原始产品需求

- **来源**：本轮用户描述“智能体也可以用 `lark-cli` 加配置档案完成更多飞书操作”，并希望技能封装常用组合调用。
- **原始需求**：在聊天协作之外，智能体可按用户要求使用所选身份访问其有权限的其他飞书能力，用户无需等待本仓库为每项能力添加专用工具。

#### 2.5.2 用户可感知行为

- **触发与前置条件**：用户明确提出另一项飞书操作并指定或确认身份；相应应用权限和用户授权已经具备。
- **主要行为**：智能体确认操作对象、身份和写入意图，利用飞书现有能力执行，并报告实际结果。
- **成功结果**：用户可完成获授权的飞书操作，不受本插件旧工具清单限制。
- **失败与边界行为**：身份或权限不足时不自动换身份；高风险或不可逆操作继续遵守宿主与飞书命令的确认要求。插件不对上游全部飞书接口作可用性承诺。

#### 2.5.3 交互设计

- 执行前向用户说明“将以「{配置档案}」的{机器人／用户}身份对「{目标}」执行{操作}”；写入范围或目标不明确时先澄清。
- 权限不足时说明当前身份缺少什么访问能力及用户可采取的授权动作，不把空结果直接解释为资源不存在。

#### 2.5.4 分项范围边界

- **本项包含**：技能指导身份选择和常用飞书操作的稳定调用方式。
- **本项不包含**：为飞书全部业务域重新定义统一接口或保证每个上游能力都具备本插件专属封装。
- **引用共享规则**：`1.3` 的身份与授权规则。

#### 2.5.5 验收映射

- `VAL-OPERATIONS-001`：聊天协作之外可使用已获授权的飞书能力。

### 2.6 安装与切换

#### 2.6.1 原始产品需求

- **来源**：本轮用户描述“不需要再构建我们自己的命令行工具”；[README](../../../README.md)当前的安装、配置与守护进程说明。
- **原始需求**：Codex 和 Claude Code 使用者可以通过插件技能完成飞书协作，不再为了常用任务安装和管理本仓库的独立命令行服务；用户自行按照 `lark-cli` 的引导创建机器人配置、登录及授权，不迁移本仓库的旧配置。

#### 2.6.2 用户可感知行为

- **触发与前置条件**：新用户安装插件，或旧用户从现有版本切换。
- **主要行为**：插件说明所需飞书配置与授权，引导用户自行完成 `lark-cli` 的机器人配置、用户登录及授权；首次协作前检查依赖与身份状态。旧用户使用同一个机器人切换接收方式前，先停止旧连接，再验证新连接；插件不读取、复制或删除本仓库的旧配置。
- **成功结果**：用户无需启动本仓库的守护进程或配置本仓库的模型上下文协议服务，即可完成 `2.1` 至 `2.4` 的协作流程；Codex 和 Claude Code 两种运行时均可使用。
- **失败与边界行为**：缺少依赖、身份无效或新连接未验证时，指出缺口和可执行的下一步；不得以成功提示掩盖实际未连接状态。新连接失败后，用户仍可按原方式恢复旧连接。

#### 2.6.3 交互设计

- 新用户缺少必要依赖时说明“尚未准备好飞书命令行工具，请先完成安装与配置”；完成配置但缺少访问权限时沿用 `2.1` 的权限反馈。
- 旧用户切换时说明“请按飞书命令行工具的引导重新配置机器人，并按需登录和授权；使用同一个机器人前请先停止旧连接”。完成真实聊天连通性检查后才说明“新连接已验证”；验证失败时说明如何恢复旧连接。

#### 2.6.4 分项范围边界

- **本项包含**：双运行时插件安装、切换指引、依赖及身份检查、新连接的可验证结果。
- **本项不包含**：自动迁移或清理旧配置与凭据、切换期间自动发布新版本。

#### 2.6.5 验收映射

- `VAL-INSTALLATION-001`：新用户无需本仓库旧服务即可完成聊天协作。
- `VAL-INSTALLATION-002`：旧用户自行重新配置并验证新连接。
- `VAL-INSTALLATION-003`：Codex 与 Claude Code 插件能力一致。

## 3. 整体不做

- 不新增持久化消息数据库或通用工作流平台。
- 不把多个聊天同时交给同一个或多个智能体会话；当前单连接约束保持到另行确认的需求变更。
- 不承诺绕过飞书身份权限、应用授权或宿主对外部写入的要求。
