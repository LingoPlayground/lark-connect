# 验收契约 — 飞书协作插件轻量化迁移

> 与 [spec.md](spec.md) 配套：规格描述为什么做和用户能观察到什么；本文件描述什么算通过。
> 一条验收断言不等于一个测试用例；实现后的结果记录在验证状态文件中。

## 1. 覆盖总览

| 规格分项 | 来源 | 验收编号 | 主要验证证据 |
|---|---|---|---|
| `2.1 选择飞书身份` | 用户关于多配置档案、机器人与用户身份的描述 | VAL-IDENTITY-001～003 | 身份选择与失败状态的契约检查；真实身份只读核查 |
| `2.2 进入目标聊天` | 当前插件聊天连接体验；用户要求组合常用操作 | VAL-CHAT-001～005 | 聊天查找与连接的行为验证；代表性真实群聊和单聊验收 |
| `2.3 处理聊天消息` | 当前插件收发、附件、提及与确认体验 | VAL-MESSAGE-001～006 | 过滤、回复与部分失败验证；真实飞书消息往返 |
| `2.4 持续响应与恢复` | 用户确认两种身份都持续响应 | VAL-CONTINUITY-001～004 | 限时监听及空窗恢复验证；两种身份的实际无人值守唤醒与补查 |
| `2.5 使用其他飞书能力` | 用户要求允许更多飞书操作 | VAL-OPERATIONS-001 | 指定身份下的代表性非聊天操作；身份及权限结果核查 |
| `2.6 安装与切换` | 用户要求退掉本仓库专用命令行工具，并确认自行重新配置身份 | VAL-INSTALLATION-001～003 | 插件载荷检查、干净环境安装、旧版切换演练；两个运行时分别验收 |

代表性真实产品验收路径：用人工用户身份向测试群明确提及目标机器人，让已连接的 Codex 会话处理并在原消息下回复、标记完成；停止活跃等待后再发一条消息，验证后续检查能够补查且不会重复回复。再以获授权用户身份连接一个测试聊天，发送一条需要回应的消息和一条无需回应的普通消息，验证两者都进入判断、周期检查、按需以本人身份回复与停止。对 Claude Code 会话至少重复两种身份各自的连接、接收、回复、确认和停止主路径。另用机器人单聊验证无需提及即可触发。验收记录只保留通用步骤与结果，不记录私人聊天内容、聊天标识或密钥。

## 2. 按产品分项组织断言

### 2.1 选择飞书身份

#### VAL-IDENTITY-001 — 身份选择贯穿协作

- **验收要求**：用户选择配置档案及机器人或用户身份后，相关飞书操作以该身份执行。
- **验证方式**：身份选择契约检查和真实只读身份核查。
- **通过标准**：执行前展示的身份与实际生效身份一致；切换档案或身份后不会继续使用旧身份。

#### VAL-IDENTITY-002 — 身份失败不静默回退

- **验收要求**：指定身份缺失、过期或无权限时，用户收到对应失败和恢复指引。
- **验证方式**：失败行为验证。
- **通过标准**：操作未由另一身份执行；反馈明确指出受影响的配置档案、身份和可采取的下一步。

#### VAL-IDENTITY-003 — 用户身份参与已连接聊天

- **验收要求**：用户选择本人身份连接聊天后，智能体可处理该聊天的合格消息并以该用户身份回复。
- **验证方式**：代表性真实产品验收路径及身份核查。
- **通过标准**：回复出现在所选聊天，由所选用户身份发送；没有使用机器人身份替代。

### 2.2 进入目标聊天

#### VAL-CHAT-001 — 定位并连接目标聊天

- **验收要求**：用户可通过群名或机器人单聊进入唯一确定的目标聊天，无需自行提供聊天标识。
- **验证方式**：代表性真实群聊与单聊验收。
- **通过标准**：会话显示正确的聊天和身份，后续只接收该聊天的符合条件消息。

#### VAL-CHAT-002 — 目标歧义与不可见可恢复

- **验收要求**：多个匹配项、找不到聊天或单聊发现超时时，智能体给用户明确选择或恢复办法。
- **验证方式**：聊天发现行为验证。
- **通过标准**：没有猜测绑定；反馈可让用户选择候选、检查机器人入群或重试单聊验证。

#### VAL-CHAT-003 — 连接冲突与聊天隔离

- **验收要求**：目标被其他会话占用时需显式接管，当前会话不会处理未连接聊天的消息。
- **验证方式**：连接与路由行为验证。
- **通过标准**：未授权的接管被拒绝；显式接管后旧会话停止响应；其他聊天消息不交给当前会话。

#### VAL-CHAT-004 — 可读取协作背景

- **验收要求**：进入聊天后，智能体可获取近期消息及可提及的参与者，供处理任务时使用。
- **验证方式**：聊天上下文与参与者读取验证。
- **通过标准**：结果足以区分消息发送者、时间、回复关系和可用提及对象；无权限时反馈原因。

#### VAL-CHAT-005 — 用户身份进入可访问聊天

- **验收要求**：用户身份可选择本人及开放接口均允许访问的群聊或单聊，且不依赖机器人加入该聊天；平台禁止读取历史的聊天不能被错误标为持续响应可用。
- **验证方式**：用户身份下的群聊与单聊发现行为验证。
- **通过标准**：目标聊天可被明确选择；不可访问的聊天不会被猜测连接或由另一身份代替访问，平台限制得到明确提示。

### 2.3 处理聊天消息

#### VAL-MESSAGE-001 — 机器人消息触发符合聊天规则

- **验收要求**：已连接群聊仅明确提及目标机器人的新消息触发任务；已连接机器人单聊无需提及。
- **验证方式**：消息过滤行为验证及代表性真实聊天验收。
- **通过标准**：普通群消息不触发；提及目标机器人的群消息与单聊消息各触发一次。

#### VAL-MESSAGE-002 — 消息协作信息可用

- **验收要求**：智能体能在需要时取得消息发送者、内容、提及、回复关系和附件。
- **验证方式**：消息内容与附件读取验证。
- **通过标准**：文本和代表性附件可用于处理；无法读取时用户看到明确受阻原因。

#### VAL-MESSAGE-003 — 结果关联原消息

- **验收要求**：智能体可以在原消息下发送文本及现有支持的图片、视频或文件，并可按需提及人类成员或其他机器人。
- **验证方式**：代表性真实飞书消息往返，辅以产物类型行为验证。
- **通过标准**：回复出现在正确聊天和原消息关系下；发送身份、产物及提及对象与用户意图一致。

#### VAL-MESSAGE-004 — 完成标记反映处理结果

- **验收要求**：处理完成后原消息出现确认反应；回复失败或尚未完成时不出现完成标记。
- **验证方式**：成功、回复失败及部分失败行为验证。
- **通过标准**：回复成功且确认成功才显示完成；回复成功但确认失败时报告部分完成并允许补确认，不再重复回复。

#### VAL-MESSAGE-005 — 重复和自身消息不形成循环

- **验收要求**：飞书重复投递、重新检查历史或智能体以所选身份发出的回复不会让同一请求再次产生回复；用户本人发送的合格指令仍可触发用户身份下的智能体。
- **验证方式**：重复消息、回复关系与发送者行为验证。
- **通过标准**：同一原消息至多产生一次任务回复；智能体自己的输出不触发新任务，用户本人发送的合格指令不会仅因发送者相同而被忽略。

#### VAL-MESSAGE-006 — 用户身份检查全部新消息并按需回复

- **验收要求**：用户身份检查所选聊天的全部新消息，由智能体按内容判断是否需要回应；无需回应的消息不被当成待回复任务。
- **验证方式**：普通消息、需要回应的消息及真实聊天往返验证。
- **通过标准**：两类新消息均被检查；需要回应时仅回复一次，无需回应时不发送无意义回复；其他聊天的消息不进入判断。

### 2.4 持续响应与恢复

#### VAL-CONTINUITY-001 — 活跃及无人值守时继续响应

- **验收要求**：用户要求持续响应后，活跃等待超时不会解除连接；会话无人值守时仍能在后续成功检查中发现新消息。
- **验证方式**：代表性真实产品验收路径，覆盖活跃等待和运行时唤醒。
- **通过标准**：两种状态收到的合格消息均进入同一会话并可完成回复；没有消息的等待超时不显示为任务失败。

#### VAL-CONTINUITY-002 — 监听空窗可补查

- **验收要求**：临时监听结束或中断期间产生、且飞书历史仍可读取的合格消息，在恢复检查时被发现；话题群中的旧话题新回复也包含在内。
- **验证方式**：真实空窗恢复验收、话题群旧话题回复验收和重复检查行为验证。
- **通过标准**：空窗消息得到一次处理；再次检查不重复回复已处理消息；检查范围不完整时显式报告，不把空结果宣称为没有新消息。

#### VAL-CONTINUITY-003 — 中断与停止可见

- **验收要求**：持续检查不可用、恢复或用户要求停止时，当前状态对会话主人清楚可见。
- **验证方式**：状态与失败行为验证。
- **通过标准**：失败时说明原因和可能的消息空窗；恢复后补查；停止后旧聊天不再触发该会话。

#### VAL-CONTINUITY-004 — 用户身份无人值守检查

- **验收要求**：用户身份连接的聊天在会话暂时无人值守时仍可发现符合触发规则的新消息。
- **验证方式**：用户身份下的真实无人值守检查与空窗恢复验收。
- **通过标准**：下一次成功检查处理目标聊天的合格消息；重复检查不会再次回复已处理消息；本地运行条件不满足时明确报告中断。

### 2.5 使用其他飞书能力

#### VAL-OPERATIONS-001 — 可按授权执行其他飞书操作

- **验收要求**：用户明确要求的非聊天飞书操作可以使用所选的已获授权身份执行。
- **验证方式**：一项代表性非聊天只读操作及权限失败验证。
- **通过标准**：执行前说明身份与目标；成功结果来自所选身份；无权限时不静默切换身份或声称资源不存在。

### 2.6 安装与切换

#### VAL-INSTALLATION-001 — 新安装不依赖旧服务

- **验收要求**：新用户安装插件后，不需要启动本仓库的独立命令行服务或模型上下文协议服务即可完成聊天协作。
- **验证方式**：干净环境安装、载荷检查及代表性真实产品验收路径。
- **通过标准**：配置身份、连接聊天、接收、回复与完成确认均不要求运行旧服务。

#### VAL-INSTALLATION-002 — 旧用户自行配置并验证新连接

- **验收要求**：现有用户按照飞书命令行工具的引导自行重新配置身份后，能验证新连接；插件不迁移本仓库的旧配置。
- **验证方式**：旧版使用场景的切换演练及真实连接检查。
- **通过标准**：同一机器人切换前旧连接已停止；用户能确认新身份和聊天连通，失败有恢复旧连接的步骤；旧配置未被插件读取、复制或删除。

#### VAL-INSTALLATION-003 — 两种智能体运行时均可使用

- **验收要求**：Codex 和 Claude Code 安装后的技能能力覆盖相同的核心聊天协作结果。
- **验证方式**：插件载荷检查和两个运行时各自的代表性真实产品验收。
- **通过标准**：两种运行时均能连接目标聊天、接收、回复、确认及停止；运行时限制有明确提示。
